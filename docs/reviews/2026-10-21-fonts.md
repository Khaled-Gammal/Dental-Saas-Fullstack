# Fonts: Cairo in the dashboard, Tajawal on the websites (2026-10-21)

The user asked for Cairo in the dashboard and Tajawal on the website. Both apps used IBM Plex Sans Arabic before. On
`v4/fonts-cairo-tajawal`.

## What changed

- **Dashboard: Cairo.** Same loading as before: self-hosted through `@fontsource` (no request to Google), weights 400,
  500, 600 and 700 (the ones the styles use). `@fontsource/ibm-plex-sans-arabic` is replaced by `@fontsource/cairo`
  in `apps/dashboard/package.json` and `src/main.tsx`. The family is named in the shared token
  `--font` (`packages/ui/tokens.css`), which only the dashboard reads as is.
- **Websites (clinic sites and the platform landing page): Tajawal.** Same loading as before: `next/font/google`, which
  downloads the font at build time and serves it from the site (`apps/web/app/layout.tsx`). `apps/web/app/globals.css`
  points `--font` at it, over the shared token.
- **Tajawal has no 600.** Google publishes 200, 300, 400, 500, 700, 800 and 900. The site loads 400, 500 and 700;
  text styled 600 (17 places on the site) renders at 700, the nearest heavier weight, by the browser's normal font
  matching. No style was changed to hide this.
- `docs/design-system.md` names the two fonts.

## Checks

- Lint and typecheck (8 tasks), the dashboard's 122 tests, the dashboard build (Cairo's files are in `dist/assets`)
  and the website build (Tajawal downloaded) pass.
- Screenshots: dashboard overview and invoices at 1440 px, overview at 390 px; clinic website at 1440 and 390 px; the
  platform landing page at 1440 px. Text renders in the new fonts and nothing scrolls sideways. Cairo's taller letters
  did not push any header, card or table row out of shape.

## Not changed

- E-mails keep `Tahoma, Arial` (mail clients don't load web fonts reliably).
- Printouts (invoice, prescription) use the dashboard's font, so they print in Cairo now.

## Smaller text in the dashboard (same day)

The user asked for smaller text to make the pages better. Cairo reads larger than Plex at the same size, and the
dashboard's body was 16px, large for a working tool.

- `theme.css` (dashboard only) re-points the scale: `--fs-sm` 13px (was 14), `--fs-md` 14px (16), `--fs-lg` 16px
  (18), `--fs-xl` 20px (22), `--fs-2xl` 24px (28). `--fs-xs` stays 12px, the smallest size kept for Arabic. Every
  screen uses these tokens, so body text, card titles, labels and hints all shrink together; Tailwind's `text-sm`
  (14px) in the shadcn parts now matches the body.
- Page titles: `clamp(1.2rem, …, 1.4rem)` (was 1.3–1.6rem). Overview figures: `clamp(1.4rem, …, 1.75rem)` (was
  1.6–2rem). Sidebar items: 14px (was 15px).
- Fields (`.input`) stay 16px at 860px and below: phones zoom into a field whose text is under 16px when it gets
  focus.
- Printouts are untouched (they use fixed sizes for paper), and so are the websites.

Checks: lint, typecheck and the 122 tests pass. Screenshots of overview, invoices, patients and the new-expense form at
1440px, overview and invoices at 390px: denser, nothing overflows, the search field on the phone is 16px.
