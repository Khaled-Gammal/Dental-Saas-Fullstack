# Review: weeks 1–2 (foundation, sign-up, login)

Three independent reviews: security, performance (with EXPLAIN ANALYZE on 90k–500k synthetic rows), QA.
Then a compile-focused review of the fixes. Database: 88 checks pass. API e2e: 27 tests.

## Fixed

| # | Area | Finding | Fix | Covered by |
| --- | --- | --- | --- | --- |
| 1 | Performance | RLS policy `IS NOT DISTINCT FROM` blocked index use: every tenant query was a full scan (51.6 ms on 90k rows) | Policies use `=` (0.14 ms); `outbox_events` has its own NULL-aware policy | `01_tenant_isolation.sql` plan check |
| 2 | Performance | 13 RLS tables had no index starting with `tenant_id` | Composite `(tenant_id, …)` indexes | migration 0004 |
| 3 | Security | OTP 5-guess limit bypassable with parallel requests (read, then increment) | Attempt claimed atomically before comparing | `locks a code after 5 wrong tries` |
| 4 | Security | Send limit and login lockout were check-then-insert races | Sends serialized by advisory lock; lockout counted atomically in Redis before scrypt | `limits code sends`, `locks login after 10 attempts` |
| 5 | Security | No rate limiting on public auth endpoints (SMS cost, scrypt CPU) | Per-IP Redis throttles on signup, login, verify, resend, slug check | config `RATE_LIMIT_ENABLED` |
| 6 | Security | OTP codes written to logs; dev SMS sender always bound | Bodies never logged; sender chosen by `SMS_PROVIDER`; production refuses `dev` | config guard |
| 7 | Security | Production could start with dev secrets, dev login or limits off | Startup refuses all of them | config guard |
| 8 | Security | DB error messages (table/constraint names) sent to clients | Static message; real one logged | `database errors never leak` |
| 9 | Security | JWT verify did not pin algorithm or issuer | `HS256` + issuer required | all authenticated tests |
| 10 | Security | API role could write plans, templates, `users.platform_role` | Revoked; column-level grants on `users` | `cannot make anyone a super admin` |
| 11 | Security | Sessions could slide forever; refresh could silently switch clinic | 90-day absolute limit; refresh ends instead of switching | `logout ends … older tokens` |
| 12 | Security | Lockout keyed on raw input; anyone could lock out a victim | Key = normalized phone/email + IP (10) and account (50) | lockout test |
| 13 | QA | Dashboard showed the previous clinic's cached data after sign-out | Cache cleared on user/clinic change; keys scoped by clinic | manual |
| 14 | QA | Arabic-Indic digits rejected in the code field | Accepted in UI and API | `Arabic-Indic digits are accepted` |
| 15 | QA | Malformed cookie or `?slug=a&slug=b` caused 500 | Safe parsing | `malformed session cookie` |
| 16 | QA | Old codes stayed valid after verification | All open codes voided on success | `the code works only once` |
| 17 | Perf | Public site: ~10 round trips per view, prices returned as strings | One JSON query (4 round trips), numbers, `Cache-Control: s-maxage=60` | public site test |
| 18 | Perf | scrypt capped at ~40 logins/s by the 4-thread pool | `UV_THREADPOOL_SIZE` = CPU cores | — |
| 19 | Perf | Pool waited forever under load; no statement timeout | 5 s connect timeout, 15 s statement timeout | — |
| 20 | Ops | Auth tables grew forever | Nightly `purge_auth_data()` job | migration 0004 |
| 21 | QA | Branch input weaker than clinic rules (untrimmed names, `-a-` slugs, raw phones) | Trim, same slug rule, phone normalized | — |
| 22 | QA | Price 0, equal ranges, rounding; RTL phone display; slug check per keystroke; labels; `role="alert"` | Fixed | manual |
