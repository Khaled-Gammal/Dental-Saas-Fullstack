# Removing the dashboard's i18n layer (2026-10-21)

The dashboard is Arabic only (L10N-001, the owner's decision). The user asked to remove the i18n layer, because there
is no second language. Before this change every text went through a dictionary (`src/i18n.ts`: 1,813 entries,
`t('key')` in 75 files, 2,117 lookups). On `v4/remove-i18n`, built on `v4/overview-redesign` (it touches the same
files).

## What changed

- **Texts are written where they are shown.** A codemod, using the TypeScript compiler and its type checker (no
  search-and-replace), did the following:
  - every `t('key')` became its Arabic text (2,104 calls);
  - every string typed as a dictionary key became its text wherever it sat: menu items, steps, tab titles,
    `Record<…, Key>` maps, conditional `t(a ? 'x' : 'y')` (2,155 strings);
  - the `Key` type became `string`.

  A second pass made the result read like hand-written JSX: `title="…"` instead of `title={'…'}` (688 places), and
  plain text instead of `{'…'}` inside elements (686 places). It only did this where the meaning is identical: no
  quotes, braces, angle brackets, `&`, line breaks, or leading/trailing spaces.
- **Values that come from data get label maps: `src/labels.ts` (new).** Statuses, payment methods, permissions, API
  error codes and the like were looked up by building a key at runtime (`t(\`status_${a.status}\`)`), in 99 places.
  They are now 45 named maps such as `appointmentStatusLabel[a.status]` and `paymentMethodLabel[p.method]`. Lookups
  with a fallback (`tOr`) became `patientFieldLabel[f] ?? f`, which behaves the same. The four helpers moved there
  unchanged in behaviour: `errorText`, `roleLabel`, `minutesLabel`, `categoryLabel`.
- **`src/i18n.ts` is deleted,** with `t()`, `tOr()`, the `Key` type and `KEYS`. Texts no code used anymore went with
  it.
- **Navigation got stable ids.** Menu entries had used their text key as their identity (the group's remembered
  open/closed state, the active group, React keys). They now have an `id` (`clinic`, `finance`, `website`, `team`) and
  a `label`; items are identified by their page. Rewording a label no longer touches anything else. Side effect: each
  member's remembered open groups reset once.
- **Tests:**
  - **Arabic only (`arabic-only.test.ts`):** it read the dictionary. It now reads the source: every text on screen (JSX
    text, and every string with Arabic in it) may carry no English words outside the same allow-list. It found «KB» (a
    file-size unit written in the code, which the old dictionary test never saw), now allowed like «MB».
  - **API error codes (`api-error-codes.test.ts`):** it checks `errorLabel`.
  - **Others:** `validation-text.test.ts` imports `errorText` from `labels`. The nav test checks ids and pages.

## Trade-off (said before starting)

Wording now lives next to the code that shows it, which is usual for a one-language app. A phrase used in several
places is edited in each.

## Not touched

- **Historical documents:** past reviews and the SRS (NFR-09, the original "Arabic and English" requirement, superseded
  by the owner's Arabic-only decision).
- **The API's and the website's own texts.** Only the dashboard had this dictionary.
