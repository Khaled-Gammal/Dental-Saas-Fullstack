# Review — Week 3: clinic setup wizard (profile, branches, hours, publish, doctors, services)

Senior-engineer review of everything added in Week 3 after step 0, run as two independent passes
(backend: API + database; frontend: dashboard). Findings were fixed in the same change set; what was
deliberately left is listed at the end.

## Scope

- API: `modules/clinic-setup/{profile,branches,doctors,services}`, `onboarding.controller.ts`,
  `modules/website` (publish + cache purge), `modules/public-site` (draft vs published theme).
- Database: `20261018000005_onboarding.sql`, `20261019000006_catalog.sql`, tests `07_onboarding.sql`, `08_catalog.sql`.
- Dashboard: `screens/{profile,hours-editor,doctors,services}.tsx`, `hours-model.ts`, `schedule-model.ts`, overview steps.
- Tests: `apps/api/test/onboarding.e2e-spec.ts`, `apps/api/test/catalog.e2e-spec.ts`.

## Patterns confirmed

- Controller (zod `.strict()` bodies, `@RequirePermission`) → service (one use case = one transaction) → repository (`tx` first, all SQL).
- Every row the UI needs comes back from one query: branches with `hours`, doctors with `branch_ids` + `schedule` as JSON aggregates (no N+1).
- Concurrent edits are serialised with `FOR UPDATE` on the parent row (branch hours, main-branch switch, doctor branches/schedule, service rules).
- Rules live in three places on purpose and agree: zod (fast 400), service (cross-field / cross-row), database constraint (the final guard, mapped to a stable error `code` in `problem-details.filter.ts`).
- Pure models (`hours-model.ts`, `schedule-model.ts`) hold the editor logic with no React, mirroring the API rules so the user never sees a server 400 for something the form could tell them.

## Findings fixed

### Backend

| # | Severity | Finding | Fix |
|---|---|---|---|
| 1 | Medium | A catalogue service could be added twice (double click, two owners). | Partial unique index `services_tenant_catalog_code (tenant_id, catalog_code)`; mapped to 409 `service_already_added`; SQL + e2e tests. |
| 2 | Medium | Doctor/service edits are live immediately but never purged the website cache (only *publish* did), so a hidden doctor stayed on the site for up to 60 s. | New `LiveSiteWrite` in `modules/website`: the same `TenantDb.run`, then `SiteCache.purge` after commit. Doctors/services writes go through it; `ClinicSetupModule` imports `WebsiteModule`. |
| 3 | Low | `branchIds: [A, A]` hit the primary key → generic 409 `conflict`. | `BranchIds` deduplicates in zod; `branch_ids` is returned sorted. |
| 4 | Low | `PATCH /services` could violate "price max ≥ price" / "has a name" and surface as a 422 from an unnamed CHECK, unlike `POST` (400). | `update` locks the row, merges the patch and runs the same `checkRules` as create. |
| 5 | Low | The schedule overlap error depended on Postgres' auto-generated EXCLUDE name. | Renamed to `doctor_schedules_no_overlap` in the migration; the error map keys on the declared name. |
| 6 | Low | Re-saving a doctor whose branch was deactivated failed with `branch_not_found`. | An inactive branch keeps its doctors (the public site hides the branch anyway). |

## Left for later (documented, not bugs)

- Read permissions: branches require `branches:read`, doctors/services have no read permission. Both are fine for the seeded roles; a `clinic:read`-style permission should be introduced when custom roles arrive.
- `POST /clinic/website/publish` bumps the version even when nothing changed. Harmless; could be conditional.
- `pendingChanges` only tracks the theme: doctors and services are live as soon as they are saved (and the cache is purged). The dashboard copy says so ("Visitors only see the last published version" refers to the brand/theme).
- Focus after closing an editor falls to `<body>` (same as the existing Branches screen) — an app-wide "return focus to the opener" helper is the right fix, not a per-screen one.
- No delete endpoints yet: doctors and services are deactivated, since both are referenced by appointments and invoices. The e2e suite deactivates what it created; run `pnpm db:reset` for a clean seed.
